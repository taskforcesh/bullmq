Reference ​

The complete API reference is generated from the source: see Relay. This page summarizes it.

Options ​

typescript
new Relay(options: RelayOptions)
OptionTypeDefaultDescription
connectionconnection optionsrequiredRedis connection (or PostgreSQL, with backend).
backendRelayBackendFactoryRediscreatePostgresRelayBackend for PostgreSQL, or a custom backend.
prefixstring'bull'Key prefix (Redis only).
namespacestring'default'Relays only exchange messages within a namespace. [A-Za-z0-9_-]{1,64}.
nodeIdstringrandomUnique id of this node. [A-Za-z0-9_-]{1,64}.
namestring–Human-readable name of the node (up to 256 characters), for dashboards.
leaseDurationnumber (ms)30000How long the node stays registered without a heartbeat.
heartbeatIntervalnumber (ms)leaseDuration / 3How often the node renews its lease.
sweepIntervalnumber (ms)leaseDurationHow often the node removes nodes whose lease expired.
maxMessageSizenumber (bytes)524288 (512 KiB)Max size of a serialized message.
inboxMaxLengthnumber10000Max unread messages kept per node; the oldest are dropped beyond it.
lagThresholdnumberinboxMaxLength / 2Emit 'lag' when a node has at least this many unread messages.
blockTimeoutnumber (ms)5000Max wait of one inbox read; on PostgreSQL, the polling fallback interval.
skipVersionCheckbooleanfalseSkip the Redis version check (on PostgreSQL, set it in connection).

lagThreshold must not exceed inboxMaxLength.

Methods ​

MethodReturnsDescription
subscribe(pattern, listener)Promise<RelaySubscription>Subscribes to a topic or pattern. Exact topics get their retained message first.
publish(topic, data, { retain? })Promise<RelayPublishResult>Publishes on a concrete topic. retain in ms keeps it as the retained message.
deleteRetained(topic)Promise<boolean>Deletes a topic's retained message; false if it had none.
waitUntilReady()Promise<void>Resolves once the node is registered and reading its inbox.
close()Promise<void>Unregisters the node and closes its connections. Idempotent.

RelaySubscription: { pattern, unsubscribe(): Promise<void> }.

retain must be a non-negative safe integer in milliseconds. Omit it or use 0 to publish without retention.

RelayPublishResult: { mid, nodes, endpoints }, the message id and how many nodes and subscriptions it was delivered to.

RelayMessage<T>: { topic, data: T, mid, ts, retained }.

Inspecting a namespace ​

Read-only getters, for dashboards and debugging. They read the datastore directly (one Lua script or SQL function call each), never the nodes, so they are cheap and safe to poll. Lists are paginated like the queue getters: start and end are inclusive positions from 0, and an end of -1 means "to the end". Orders are stable, so pages don't shift as nodes heartbeat.

MethodReturnsOrder
getCounts(){ nodes, subscriptions, patterns, retained }–
getNodes(start?, end?)RelayNodeState[]Registration
getSubscriptions(filter?, start?, end?)RelaySubscriptionState[]Node, subscription, pattern
getPatterns(start?, end?)RelayPatternState[]Pattern
getRetained(start?, end?)RelayRetainedState[]Expiry
getNamespaces()string[]Name
  • RelayNodeState: { id, info: { name?, host?, pid?, version? }, registeredAt, leaseUntil, lastHeartbeat?, backlog, dropped, subscriptions }. backlog and dropped are updated on each heartbeat. A node whose lease expired is listed (without its info) until it is swept.
  • filter is { nodeId } or { pattern }; RelaySubscriptionState is { nodeId, endpointId, pattern } (one entry per subscription).
  • RelayPatternState: { pattern, subscriptions }.
  • RelayRetainedState: { topic, mid, ts, data, expiresAt }, with data as serialized (JSON).
  • getNamespaces() lists the namespaces of the datastore (or Redis prefix) with live nodes or retained messages.
typescript
const { nodes, subscriptions } = await relay.getCounts();
const firstPage = await relay.getNodes(0, 19);
const subscribers = await relay.getSubscriptions({ pattern: 'jobs.*.cancel' });

Events ​

EventArgumentsWhen
'error'ErrorA listener failed, or a background operation (heartbeat, sweep, inbox read) failed.
'recovered'–The node was swept while running, registered again and restored its subscriptions.
'swept'string[]This node removed expired nodes.
'lag'numberThis node has at least lagThreshold unread messages (checked on every heartbeat).

Errors ​

Operations rejected by the datastore throw a RelayError with a code from RelayErrorCode:

CodeValueMeaning
InvalidTopic-1The topic doesn't follow the rules.
InvalidPattern-2The pattern doesn't follow the rules.
NodeNotRegistered-3The node was swept; it recovers on its next heartbeat.
DataTooLarge-4The serialized message is larger than maxMessageSize.
InvalidId-5Invalid node or subscription id.
IncompatibleLayout-6The namespace is in use by nodes of an incompatible BullMQ version (Redis).

Using a relay after close() throws Error('Relay is closed').

typescript
import { RelayError, RelayErrorCode } from 'bullmq';

try {
  await relay.publish(topic, data);
} catch (err) {
  if (err instanceof RelayError && err.code === RelayErrorCode.DataTooLarge) {
    // publish an id instead, and let receivers fetch the data
  }
}
