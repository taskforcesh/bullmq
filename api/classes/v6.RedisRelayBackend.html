    Class RedisRelayBackend

    Redis implementation of IRelayBackend. Every operation is one of the relay* Lua scripts; this class only passes arguments and decodes results.

    Keys of a namespace live under {prefix}::relay:{<namespace>}:

    • The empty segment after the prefix keeps the relay out of the queues' keyspace: every queue key (jobs included) is {prefix}:{queue}:... with a non-empty queue name, so no queue (not even one named "relay") nor any of its jobs can ever collide with a relay key.
    • Every key ends with a fixed word that is not a queue key suffix, never with a node id or topic, so tools that discover queues by key suffix (*:*:id, *:*:meta) never mistake relay keys for queues.
    • The namespace is a hash tag, so on Redis Cluster each namespace is one slot (the unit of scale) whatever the prefix.
    Key Type Content
    :layout hash layout version
    :nodes sorted set node → lease deadline
    :started sorted set node → registration time
    :{id}:node hash info, hb, backlog, dropped; expires with the lease
    :{id}:inbox stream the node's messages; expires with the lease
    :subs sorted set subscription index (see includes/relayIndex.lua)
    :cleanup sorted set removed nodes whose subscriptions are being pruned
    :retained sorted set topic → expiry
    :{topic}:ret hash retained message (m, ts, d)
    :mid string message id counter (starts at the server time in µs)

    Every key expires on its own when the namespace has no live node (and no retained message), so nothing is left behind even if no node sweeps it. {prefix}::relay:namespaces (sorted set: namespace → in use until) lists the namespaces in use, and expires on its own as well.

    Each node's inbox is a stream, read with a blocking XREAD on a dedicated connection. Entries published while that connection is reconnecting are read once it's back.
